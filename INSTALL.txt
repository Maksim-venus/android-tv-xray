Passwall TV 0.1.9 — install notes
================================

Pick one APK:

  Android 7.1+ (API 25) / old box / Linux kernel 4.x / 32-bit
    Passwall-TV-legacy-0.1.9.apk
    package: com.passwall.tv.legacy
    minSdk: 25
    ABIs: armeabi-v7a + arm64-v8a

  Android 12+ (API 31) 64-bit TV
    Passwall-TV-modern-0.1.9.apk
    package: com.passwall.tv
    minSdk: 31
    ABI: arm64-v8a

If you are not sure, install legacy. The two packages can be installed together.

Signing: this 0.1.9 build uses a new long-lived release key. It does not match
v0.1.7, v0.1.8, or the first v0.1.9 upload. Uninstall the older package once
(that clears saved nodes and the auto-reconnect flag), then install this APK.
Every later update is signed with this same key and installs over the top
(`adb install -r`) without another uninstall.

Sideload (USB file manager or adb):

  adb connect <tv-ip>:5555
  adb install -r Passwall-TV-legacy-0.1.9.apk

Fresh install has no built-in nodes. On the TV: Settings → enable insecure SSL if needed → enable HTTP edit → open the shown http://192.168.x.x:8787 URL from a phone on the same LAN → import vless:// or vmess:// → select the node → 启动 → accept the system VPN dialog.

Android 7.1 (API 25) caveats for the legacy APK:

  - Install requires API 25+. Android 7.0 (API 24) and older are not supported.
  - TUN/VPN must exist on the box. VpnService.establish() fails when the kernel has no /dev/tun (CONFIG_TUN missing) or the ROM hides the VPN consent screen. The app shows a Chinese error instead of pretending the proxy started.
  - IPv6 routes are off on legacy. Many API 25 boxes mishandle IPv6 default routes.
  - Foreground-service types and notification channels in the manifest apply on newer Android only. API 25 starts the VPN with startService + startForeground and does not create a notification channel.
  - Flag emoji in the connectivity test may show as two letters. The exit IP still comes from ipinfo.io.
  - This build still embeds AndroidLibXrayLite v26.1.13 (real libv2ray / libgojni.so, allowInsecure + TUN startLoop). It is not a stub core.

Launch screen (0.1.9):

  - The first frame after you open the app is a light splash: logo and "Passwall TV".
  - It stays until the home screen is ready. There is no extra wait after that.
  - Copying and checking geosite/geoip, and loading the Xray native library, no longer
    run on the main thread at startup.

Auto-reconnect (since 0.1.8), including 当贝 / Dangbei boxes that kill background apps:

  - After the tunnel comes up, Passwall stores "VPN should be on" and the selected node id.
  - Pressing 停止 clears that flag. A deliberate Stop does not auto-restart.
  - If the process is killed while the flag is set, VpnService returns START_STICKY
    (on API 25 the system recreates the service with a null intent) and a ~15s
    watchdog alarm starts the process if the ROM ignores sticky services.
  - Boot, quick-boot, and app update also restore when the flag is still set.
  - Many Dangbei ROMs drop the VPN consent when they kill the app. The system
    then shows the VPN permission dialog again. The app cannot accept it silently:
    you get a Chinese toast and, when the screen can show it, the system dialog.
    Open Passwall and tap 允许 if the tunnel does not return.
  - If the box has 自启动, 后台运行, or a battery whitelist, add Passwall.
    Legacy package name: com.passwall.tv.legacy.
  - A force-stop from system settings cancels alarms until you open the app once.
    Opening it tries to restore.
  - Failed starts back off (2s, 5s, 15s, 30s, 60s, 120s) and stop after 6 failures.
    The reason is written to the web admin 日志. A kill after a healthy start
    does not consume those retries.
  - If the app process stays alive but the Xray core stops (startLoop/core exit,
    or 127.0.0.1:10808 stops accepting), Passwall restarts that core on the same
    TUN and node. That path has its own 6-try cap and Chinese web-admin logs.
    Pressing 停止 cancels it. A core that stays up for about a minute clears the count.
  - After a successful start, if geoip/geosite were never updated or are older than
    7 days, Passwall downloads them (mainland mirrors first; GitHub last). The web
    admin 系统 page shows the last success time, or a Chinese failure reason instead
    of staying on 「尚未更新」. 「立即更新」 retries without waiting.
